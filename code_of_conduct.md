# Участь у розробці

Дякую за інтерес до проєкту **«Менеджер контактів із групами»**!

Будь-які пропозиції щодо покращення проєкту, виправлення помилок та доповнення функціональності вітаються.

## Як зробити внесок

1. Створіть fork репозиторію.
2. Створіть окрему гілку для своїх змін:

```bash
git checkout -b feature/my-change
```

3. Внесіть необхідні зміни.
4. Перевірте, що проєкт працює коректно.
5. Запустіть тести:

```bash
python3 -m unittest tests.test_csv_processor -v
```

6. Зробіть commit зі зрозумілим описом:

```bash
git add .
git commit -m "Додано нову функціональність"
```

7. Відправте гілку до свого fork:

```bash
git push origin feature/my-change
```

8. Створіть Pull Request до основного репозиторію.

## Повідомлення про помилки

Якщо ви знайшли помилку:

* перевірте, чи немає вже відповідного Issue;
* коротко опишіть проблему;
* вкажіть кроки для її відтворення;
* за можливості додайте повідомлення про помилку або скріншот;
* зазначте середовище, у якому виникла проблема.

## Пропозиції щодо нових функцій

Перед реалізацією великої функціональності бажано створити Issue з описом:

* що саме потрібно додати;
* яку проблему це вирішує;
* як приблизно має працювати нова функція.

## Вимоги до коду

Під час роботи над проєктом бажано:

* дотримуватися наявної структури проєкту;
* не додавати зайві залежності без необхідності;
* давати зрозумілі назви змінним, функціям і класам;
* не залишати налагоджувальний код у готовому рішенні;
* не додавати паролі, ключі API та інші конфіденційні дані до репозиторію;
* перевіряти зміни перед створенням Pull Request.

## Тести

Для перевірки Python-модуля використовується `unittest`.

Перед створенням Pull Request необхідно запустити:

```bash
python3 -m unittest tests.test_csv_processor -v
```

Нові функції бажано супроводжувати відповідними тестами.

## Pull Request

Pull Request повинен:

* містити короткий і зрозумілий опис змін;
* стосуватися однієї задачі або функціональності;
* не містити непов'язаних змін;
* не порушувати роботу вже наявного функціоналу.

У описі Pull Request бажано вказати:

**Що змінено:**

* ...

**Що виправлено:**

* ...

**Як перевірити:**

* ...

## Кодекс поведінки

Усі учасники проєкту повинні дотримуватися правил, описаних у файлі [code_of_conduct.md](code_of_conduct.md).

Дякуємо за внесок у розвиток проєкту! 🚀
